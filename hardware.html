电脑输入 packet，MCU 负责收发切换

电机 ← 三态缓冲器 ← 电平转换器 ← MCU ← 电脑。回复沿接收通道反向返回。电脑无需控制 DIR，板端桥接固件负责。

全部信号线与电源

教学假设：MCU I/O 与三态缓冲器供电均为 3.3V，电平转换器旁路；执行器使用外部 5V。真实电压、接口引脚与电源容量需按所选器件适配。

一个 GPIO 同时控制两个缓冲器

OE = Output Enable（输出使能），就是缓冲器的“门”。7 脚 OE2 是高电平开门；1 脚 /OE1 名字前带“/”，是低电平开门。两个脚接同一根 DIR，所以 DIR 一变，两扇门总是一开一关。

DIR1脚 /OE1（低有效）7脚 OE2（高有效）结果
1 / 高高 → 接收门关高 → 发送门开MCU TX → DATA → 电机
0 / 低低 → 接收门开低 → 发送门关（高阻）电机 DATA → MCU RX

“高阻”表示发送输出像拔掉插头一样松开数据线，既不输出 1 也不输出 0。芯片本身不认识 Ping、不计算 CRC、不知道什么时候发完。MCU 固件负责设置 DIR。

软件和硬件各自做什么

硬件：让电信号可靠到达

  • USB/VCOM：电脑与开发板之间的字节通道。
  • MCU：提供 UART TX/RX 和 GPIO DIR。
  • Level shifter：匹配电平，不能替代 DIR 控制。
  • 三态缓冲器：根据 DIR 开关发送/接收通道。
  • 执行器：收指令、执行动作、生成回复。
  • 电源与 GND：电机 5V、接口 3.3V，共同参考地。

软件：决定字节与切换时机

  • 电脑程序：输入或生成包，校验与显示。
  • MCU 固件：收齐完整 Instruction Packet。
  • 固件：DIR=1，UART 发送，等 TX_COMPLETE（不是 FIFO_EMPTY），DIR=0。源码见 firmware/main.c。
  • 固件：接收原始 Status，再转发回电脑。
  • 电机内置固件：检查 ID/CRC，读取或写入控制表。
  • 本演示程序：模拟上述过程，不操作真实接口。

为何不能只按示意图判断电平兼容？

教学假设：执行器回复高电平为 3.3V；若缓冲器在 5V 供电时的输入高电平门限为 0.7×VCC，则需要至少 3.5V。此时 3.3V 回复可能无法正确识别。这仅是门限算例，各器件的供电范围、输入门限与耐压需要按实际规格核对。

只在 MCU 与三态芯片之间加入 3.3V/5V level shifter，不能自动解决电机 DATA 到缓冲器 A1 的门限。因此模拟默认用 3.3V 缓冲器；若必须采用 5V 方案，需要重新核对电机侧转换电路与门限。

通信成功怎么判断？

  1. 先 Ping：收到了 ID 正确、Length 正确、CRC 正确的 Status Packet。
  2. Write：检查 Error=0，说明写操作被接受。
  3. Read Present Position：检查位置是否达到目标。Write 成功不等于动作已完成。
  4. Write 没有回复：也可能是 Status Return Level=0/1，而不是线路故障。Ping 不受该设置影响。

原始包结构：FF FF FD 00 | ID | Length_L Length_H | Instruction | Parameters | CRC_L CRC_H。Status 的 Instruction 为 55，后面增加 Error 字节。
