# Serial Actuator Lab · 串口执行器通信实验室

面向初学者的 3D 通信教学模拟：电脑 → MCU → 电平转换 → 双通道三态缓冲器 → 执行器，再将状态包传回电脑。

每个字节在硬件连线和 MCU 内部的传输都有动画，右侧同步高亮通用 C 桥接源码。支持单步、自动播放、角度控制流程与故障实验。它不会打开真实串口或连接硬件。

## 快速开始

需要 Python 3.12 或兼容版本、图形环境和中文字体。在本目录运行：

```sh
python -m venv .venv
```

使用虚拟环境自身的 Python 安装依赖：

```powershell
# Windows
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

```sh
# Linux
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python app.py
```

Windows 也可双击 `start.cmd`。启动脚本会使用本目录或父目录的 `.venv`。中文字体可通过环境变量 `SERVO_LAB_FONT` 指向任意可用的中文字体文件。

## 第一次操作

1. 左侧点击「① Ping」，载入完整指令包。
2. 右下点击「下一步」，看每个步骤的连线、芯片内部和代码变化。
3. 第 04 步看到 DIR 从 LOW 变为 HIGH，发送门打开，接收门关闭。
4. 第 07 步看到 DIR 回到 LOW，发送输出变成高阻，接收门打开。
5. 第 12 步底部显示完整状态包及校验结果。
6. 点击「自动走完整流程」：Ping → 读取模式 → 开启扭矩 → 写角度 → 重复读位置，直到到达目标。

Write 成功仅表示写指令被接受；是否到位需读取当前位置。暂停教学动画不等于对真实执行器执行急停。

## 上一步与当前位置

「上一步」按钮（或键盘 Backspace）退回上一格，电机状态也一起恢复，退回后那一格的动画会再播一遍。每一步都会标出当前在哪个部分：3D 视图里，当前部分变亮并显示「▼ 现在在这里」，其他部分变暗；硬件面板顶部的位置条（电脑 → MCU → 电平转换 → 三态缓冲器 → 执行器）会点亮经过的部分；步骤说明上方也有一行「当前位置」。

## 讲解：新手 / 专业

右下步骤面板右上角的「讲解」开关默认是「新手」。新手版用一个比喻贯穿全程：MCU 是一间收发室，CPU 是办事员，UART 是收发窗口，FIFO 是排队的传送带，SRAM 是笔记本；电机那根 DATA 线像对讲机，按住说话键（DIR=1）才能说，松开（DIR=0）才能听。每一格分三段：【比方】、【实际】、【新词】，一次只解释一个新词。切到「专业」可以看到原来的技术说明。

## 细化 MCU：芯片内部逐位看

放大镜右上角的「细化 MCU」默认打开。打开时，第 01、02、03、04、05、10、11 步之前会先插入共 17 格细节，「下一步」一格一格走，放大镜切到「位级细节」页，代码面板高亮 `main.c` 里带字母的标签（如 `[02b]`）：

| 细节 | 内容 |
|---|---|
| 01a | 上电初始化：时钟、波特率分频与误差、GPIO 方向、millis() 定时器 |
| 02a～02c | UART 接收器：下降沿与半位确认、16 倍过采样、移位寄存器逐位拼字节、停止位检查、进 RX FIFO |
| 02d | CPU 轮询 RX_EMPTY，经总线读数据寄存器；轮询和中断的区别 |
| 02e | 包头比对状态机，含多余 FF 的重新同步例子 |
| 03a～03c | 长度字段（小端）算 need、范围检查防越界、收齐退出循环 |
| 04a～04b | 发送前清空电机侧 RX FIFO；GPIO 输出寄存器与推挽驱动 |
| 05a～05d | TX_FULL 检查、写数据寄存器入 FIFO、加起始位和停止位、波特率发生器逐位移出 |
| 10a | 带 20ms 超时的等待，millis() 的 1ms 分辨率 |
| 11a | 回传电脑前同样检查 TX_FULL |

时钟 48 MHz、分频值、状态寄存器位名都是举例，不对应某款具体芯片。关掉「细化 MCU」即回到原来的 12 步。

## 示例协议和寄存器

教学二进制帧：`FF FF FD 00 | ID | Length_L Length_H | Instruction | Parameters | CRC_L CRC_H`。
支持单播 Ping(01)、Read(02)、Write(03)；状态包指令为 55，附加 Error 字节。协议实现包含 CRC-16 和字节转义。

模拟设备 ID=1，演示设备编号=1，演示固件版本=1。电机初始角度 180°，模式 3，扭矩关闭，模拟通信速率 57,600 bps，8N1。

| 地址 | 教学含义 | 长度 |
|---|---|---|
| 11 | 模式，3 表示位置控制 | 1 |
| 64 | 扭矩使能，0/1 | 1 |
| 68 | 状态回复策略，0/1/2 | 1 |
| 116 | 目标位置 | 4 |
| 132 | 当前位置 | 4 |

角度换算：`ticks × 360 / 4096`。这些是本模拟的数据定义，不代表所有实际设备都支持。Ping 示例：`FF FF FD 00 01 03 00 01 19 4E`。

## 通用硬件与固件

打开 `hardware.html` 查看信号图。图中的 GPIO、UART 名称是通用信号名，不对应某块板子的实际引脚。

- MCU：电脑侧 UART0、执行器侧 UART1、方向 GPIO。
- level shifter：按真实接口电平选择；默认 3.3V 方案旁路。
- 三态缓冲器：DIR=1 开 TX/关 RX；DIR=0 让 TX 高阻/开 RX。
- 电源：示例执行器使用外部 5V、逻辑接口使用 3.3V，各部分共地；真实设备需按实际规格选择。
- 固件：先收齐包，再 DIR=1、发送、等最终停止位出线、DIR=0，最后收回包并转发。

`firmware/board.h` 只声明平台适配接口。`firmware/main.c` 是通用教学桥接代码，不包含板级驱动或可直接烧录的工程。迁移时需实现串口读写、GPIO、时钟和 `uart_tx_complete()`；不能把 FIFO 空当成最后停止位发送完成。

`FIFO_EMPTY` 与 `TX_COMPLETE` 是教学状态名；位号、状态寄存器地址和 FIFO 深度依硬件而异。本演示将 FIFO 画成 16 格。

## 验证

```sh
python -m unittest discover -s . -p test_protocol.py -v
python app.py --screenshot
```

请使用已安装依赖的虚拟环境 Python。协议测试覆盖已知帧、CRC、转义、模式与扭矩、位置读写、错误数据和回复策略。图形场景检查覆盖 12 步、发送完成时序、90° 全流程、故障实验、输入校验和日志导出。

截图和 JSON 日志生成于 `output/`，默认不纳入版本控制。演示动画刻意放慢；不模拟真实电气波形、负载或完整设备固件，不能用模拟成功证明实物通信成功。
